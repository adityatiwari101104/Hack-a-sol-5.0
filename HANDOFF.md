## 1. The project in one paragraph

Team: Gaurav + Tiwari. Problem statement **AIML-02 "Zero-Guessing & Contradiction-Checking Document AI"**
(see `Hackasol_5.0_Problem_Statement.pdf`): multi-PDF Q&A where every answer cites **document, page and a verbatim
quote**, detects **contradictions** between documents, follows **amendment chains**, **abstains instead of guessing**,
and reports a **faithfulness score**. Bonus points: PDF highlight, Hindi, calculations.
Our build is **Proof-or-Silence**: a compliance assistant for the officer of a fictional Tier 3 Urban Co-operative
Bank, over 15 ingested RBI PDFs (16 downloaded; see §2) + 7 fictional bank documents (loan agreements, policies, FAQ with a planted prompt
injection). **Core principle: OpenAI only drafts and extracts; our code decides what the user sees.**

Status: **backend frozen after the final pass (§0)**; the UI is built in `frontend/` by the UI session.

## 2. Hard constraints (keep these)

- **LLM:** the organizer explicitly allowed an OpenAI API key (the PS wording about open-source models is not a blocker).
  Models: drafting `gpt-5.4-mini-2026-03-17`, extraction/plan/judge `gpt-5.4-nano-2026-03-17`; fresh test set was
  generated by `gpt-5.4`. Do not claim a different LLM was used anywhere (docs, slides).
- **Budget: $6 total for the whole project.** Code default cap `SPEND_CAP_USD=3.50` (`backend/app/config.py`); live
  work runs with `SPEND_CAP_USD=5.70` in the environment. Spend ≈ **$5.14** (`eval/spend_ledger.json`). The system refuses calls at the cap.
- **API key** is read from the file in `LLM_KEY_FILE` (default `~/Janmitra/.env`, line `OPENAI_API_KEY=...`).
  It is never printed or committed. On a new machine/account set `LLM_KEY_FILE` to wherever the key lives.
- **`LLM_MODE=replay`** answers only from recorded responses in `eval/cassettes/` → **$0, deterministic**.
  Use replay for all re-scoring. Changing any prompt/schema/model invalidates cassettes (= live spend).
- **15 of the 16 RBI PDFs are ingested.** `corpus/real/rbi` also holds KFS Annex A (`2024-04-15_kfs-annex-a-template_…`),
  the blank KFS template: a 2-page form of placeholders and footnotes with no rule or value to cite. It is left out of
  `corpus/registry.json` on purpose; adding it now would change the search index for every question and invalidate
  every recorded answer (~$0.9 to re-record). The UI's `/documents` count (15 RBI + 7 bank = 22) is correct.
- **RBI PDFs are not committed** (copyright). They were downloaded by hand (RBI's site has a bot check — never
  script around it). URLs: `corpus/sources.csv`; checksums: `corpus/real/rbi/SHA256SUMS`; manifest: `corpus/MANIFEST.csv`.
- Commit only when asked; don't push unless asked. Tell the user before deleting anything.
- User preference: **be fast and efficient**; explain things simply (the team asked many "how does X work" questions).

## 4. Architecture (where things live)

```
PDF ─ backend/app/ingest.py   pdfplumber words+bboxes; clause tree e.g. 261(2)(ii) with inherited lead-in;
      │                       footnotes; cross-page table stitching; hidden white text flagged (never evidence);
      │                       RBI 'Withdrawn' stamp + header/footer removal
      ├ extract.py            glossary; footnote amendment versions; repeal/withdrawal edges; REFERS_TO;
      │                       value tuples (nano, quote-checked) + audit (mini) + code rules
      └ pipeline.py           -> SQLite (db.py): documents, chunks, provision_versions(valid_from/valid_to),
                                 edges, value_tuples, trace_log ...   + contextual prefixes for 1,923 chunks
question ─ service.ask:
  1 understand      nano: sub-queries, subjects, case facts, Hindi→English, premises
  2 retrieve.py     BM25 (bm25s) + dense (BAAI/bge-small-en-v1.5), RRF k=60 over top-200 each, TOP_K_CHUNKS=8
                    per query, ≤4 queries, synonym expansion, graph_expand (REFERS_TO 1 hop + all versions, cap 6),
                    withdrawing clause added; optional cross-encoder RERANK=1 (OFF: 28/32 recall either way)
  3 build_evidence  sentence-level rescoring → max 18 evidence sentences (≤3 per chunk); in-force first
  4 applicability.py + rule_findings: code compares case facts with rule conditions (R1, R2 … findings);
                    gap detection; residual clause 261(5); product-scope filter
  5 privacy.py      Presidio PII redaction (+ Indian recognizers, IFSC, account no.) before text leaves the machine
  6 draft           gpt-5.4-mini, structured outputs; DRAFT_SYSTEM (service.py ~line 301): "at most 4 sentences",
                    one claim per sentence, cite E/R ids, never compute numbers ({{calc:N}} placeholders)
  7 verify.py       per sentence: (a) ids exist (b) fact sentences cite only IN_FORCE evidence (c) quote located
                    exact/fuzzy ≥95 (d) every number/date in evidence/question/calc + numeric binding
                    (e) support: coverage ≥0.8 → HHEM-2.1 ≥0.5 → MiniCheck-DeBERTa-L ≥0.5 → nano judge (≤3/answer)
                    (f) conflict triage → CONTESTED. Failing sentences are BLOCKED (never shown).
  8 repair          if NO core sentence passed: ONE retry, same system prompt + same evidence + an appended
                    paragraph listing each blocked sentence and its reason; the retry faces the same checks.
                    Sentences are tagged attempt=1/2 ("Draft 1 / Draft 2" in show.py and ask.py).
  9 calc.py         Python Decimal EMI / APR (IRR) / total interest / prepay charge with amortisation working
 10 contradict.py, impact.py (impact alert: which bank clauses a circular now conflicts with), audit.py
                    (hash-chained trace_log: row_hash = sha256(prev_hash || canonical_json(row)); verify_chain)
```

**The "graph"** is not a graph DB: it is the `edges` table (WITHDRAWS / AMENDED_BY / REFERS_TO, each with a located
verbatim quote) + `provision_versions`. Built in `pipeline.py` (`ingest_doc`, `link_documents`) with seeds from
`corpus/registry.json`; used in `retrieve.graph_expand` and `service.py` (~lines 82–88, 221–227); timeline API in `api.py`.
Status (IN_FORCE / SUPERSEDED / NOT_YET_IN_FORCE) is **computed at the as-of date, never stored**.

## 6. Key decisions and why (from team Q&A)

- **Why AIML-02:** best fit for our RAG experience and strongest UI/demo potential.
- **Hybrid search ≠ semantic search:** BM25 catches exact terms ("261(2)(ii)", "₹50 lakh"), dense catches meaning;
  RRF merges ranks without tuning weights.
- **Chunking:** clause-level (the document's own structure) beats sliding windows for regulations; sentence-level
  evidence on top so quotes are short and checkable.
- **Graph (Tiwari's idea):** the novelty is not "GraphRAG"; it is typed legal edges with proof quotes, so the system knows
  which rule replaced which and when. Without it, plain RAG cites withdrawn circulars confidently.
- **In force vs superseded:** a rule's text can still be in the PDF after it was replaced; we track valid_from/valid_to
  from RBI footnotes/withdrawals and only let *in-force* text support a present-tense answer.
- **Top-k / rerank:** we take top-200 from each retriever, fuse with RRF, keep 8 chunks per query, rescore to 18 sentences;
  the cross-encoder reranker was tested and gave no gain, so it is off.
- **Why the AI writes sentences at all:** quotes alone don't answer "does this apply to my ₹40 lakh MSE loan?". The AI
  only phrases; facts come from quotes found by search and checked by code; unprovable sentences are deleted.
- **Draft → blocked → retry:** the AI is told "at most 4 sentences"; output is a list of sentences, each verified alone.
  If none of the core sentences pass, one retry gets the exact block reasons. Not "retry until it passes": same evidence,
  same bar, max one retry, both attempts logged.
- **Mid-evaluation doc:** user asked to strip OpenAI from it; we declined to name a fake LLM (honesty) — the team edited it
  themselves. Exported PDF: `docs/Proof-or-Silence-Mid-Evaluation.pdf`. (The claude.ai artifacts/Claude Doc made for it
  belong to the old account and may not be reachable from the new one; the PDF is the durable copy.)

## 9. Known bugs / weaknesses (from the backend gap analysis — all $0 to fix)

1. **Abstention labelling:** refusal regex in `service.py` (~line 478) misses "could not find", "does not give" → correct
   refusals score as PARTIAL. No out-of-domain gate before drafting.
2. **Faithfulness score is tautological (always 100%).** Report draft → final (e.g. "61% of drafted sentences passed;
   100% of shown sentences verified; N blocked"). `draft_total` mixes both drafts after a retry.
3. **Hindi:** plan sets `lang` but nothing uses it → answers always English. Translate the verified English answer and
   show both; Hindi source docs not ingested; only 1 Hindi gold item.
4. **Impact reports duplicate:** `/impact/{id}/export.md` re-runs `impact.run` and inserts rows; every POST /impact too.
5. **Maker-checker:** any actor except the literal "officer" can sign off; checker ≠ maker not enforced.
6. **Audit gaps:** `corpus_hash` never set on ask traces; raw question stored unredacted; question sent to OpenAI before redaction.
7. **Demo robustness:** no model warm-up at startup; `db.connect()` re-runs schema each call, no WAL, no indexes; no OpenAI
   timeout / refusal handling; spend-cap check not atomic; replay cache miss → bare 500.
8. **Ingestion:** scanned PDF → 0 chunks silently (no OCR); no runtime upload endpoint; adding a doc re-embeds everything.
9. Faithfulness of the eval itself: 34 generated fresh questions not hand spot-checked yet.

## 11. One-liners for judges
