# Prove the verifier works, then show it

**The backend is finished enough. The next points come from proving that the verifier does the work and putting that proof on screen.** Proof-or-Silence already does something no open-source platform, RBI peer repo or commercial legal/RegTech product publicly claims: it locates every quote on its page, checks the quoted clause was in force on the as-of date, sorts contradictions into conflict, supersession and different condition, and refuses in code. That is how it scores 85% on a fresh 34-question set with 0 fabricated quotes, against 50% for plain RAG. A sharp judge will press on four weak spots. Abstention precision is **0.50 on every split** and recall is **0.20 on the fresh set**. The "final faithfulness" score is **100% by construction**. Hindi answers never come back in Hindi. And the measured latency (canary p50 4.2 s and p95 14.4 s with almost no live LLM time) comes from cold model loads and repeated local embedding, not from OpenAI. Almost every fix for these costs **$0**: the LLM cassettes let all three eval splits be re-scored offline whenever a change touches only code that runs after the draft. Tokens are cheap at about **$0.0045 per question at list price**. About 40% of that can be removed, mostly hidden reasoning tokens and evidence formatting. But each of those changes edits a prompt, which invalidates the cassettes, so before judging they belong on a slide, not in the code. There is no UI yet. The category's standard pattern is inline chip → hover quote → highlighted PDF pane. The way to beat it is to show what no surveyed product shows: sentences being proven or withheld live, the citation's validity status on the chip itself, and an as-of control that changes the law under the answer. The plan at the end splits ~2.5 days into a backend track and a UI track. It spends under $0.50 of the ~$1 left and keeps the rest as a demo reserve.

A note on the budget. The ledger shows **$2.77 spent of the $4 project cap**, but the code's `SPEND_CAP_USD` defaults to $3.50, so only **$0.73** can be spent before the hard stop ([spend_ledger.json](../eval/spend_ledger.json); [README](../README.md)). Everything below fits inside $0.73. Raise the cap to $3.77 only if you consciously decide to spend the final dollar.

## Four visible weaknesses outrank any new feature

### Abstention is the weakest number, and it is a classification bug

All five must-haves in the problem statement are implemented. The metric a judge will notice first is abstention: precision 0.50 on dev, test and fresh, and recall 0.44, 0.60 and **0.20** respectively ([eval/reports](../eval/reports/)). Most of the misses are correct refusals that get filed under the wrong outcome. Fresh item f028 ("I could not find a document in force that states the interest rate for two-wheeler loans"), f033 (an out-of-scope request to name a mobile app) and dev q051 ("weather in Raipur") all end as PARTIAL. The grader labels them Accurate, but the abstention metric counts only `outcome == "ABSTAIN"`. The `REFUSAL` regex in `service.ask` catches "does not contain" and "cannot determine" but misses "could not find", "does not give" and "evidence … only shows" ([service.py](../backend/app/service.py)). There is also no out-of-domain gate before drafting. The only pre-draft gate is bge-small cosine below 0.55, and "weather in Raipur" passed it and spent a draft call. The other half of the precision loss is real over-refusal on answerable KFS table questions (test q012–q014, dev q057), which the README already lists as the main known gap.

The fix has three parts. Widen the refusal regex. Classify an answer as ABSTAIN when every core sentence is a refusal and none carries a rule finding or a quantity; that guard stops a genuine "No, this is not permitted" from being demoted. And add a pre-draft gate that abstains when the plan finds no subjects, an empty case and low similarity to banking chunks. All of this runs after or before the cached draft, so dev, test and fresh can be re-scored in replay for $0. Expect fresh recall to move from 0.20 toward roughly 0.6–0.8. That is an estimate from reading the failing rows, not a measurement. The README allows one more declared test run, so log the replay re-score of test as that run.

### Replace the tautological 100% with three numbers

Today `final_pass` and `final_total` are both `len(shown)`, so final faithfulness is always 1.0. After a repair round, `draft_total` also mixes sentences from two attempts ([service.py](../backend/app/service.py)). The honest pre-gate number exists already: mean draft faithfulness is **0.614 on test, 0.701 on dev and 0.837 on fresh** ([eval/reports](../eval/reports/)). The problem statement defines faithfulness as the share of answer sentences backed by a matching source quote. RAGAS uses the same ratio, supported claims over total claims ([RAGAS](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)). So report three numbers per answer. First, draft faithfulness per attempt. Second, the PS-literal final ratio (shown sentences with a located quote over shown sentences, with code-computed statements counted separately). Third, an independent HHEM-only score on the final sentences. "Draft 61% → 2 blocked → final 100%" tells the story. "100%" on its own invites the word "tautological". The fix takes an hour and costs $0.

### Hindi is half a bonus, and robustness to a judge's own PDF is missing

The planner sets `lang: hi` and translates the question, but nothing downstream reads `lang`, so answers always come back in English. Only one Hindi gold item exists ([service.py](../backend/app/service.py); [gold.jsonl](../eval/gold.jsonl)). The cheapest complete fix keeps verification in English and translates the *verified* sentences, labelled "machine translation of the verified English answer", with the verbatim quotes left in English. One nano call per answer costs about $0.0002. IndicTrans2-dist (MIT, ~0.3B, Hindi included) does it for $0, but it is gated on Hugging Face, recommends a GPU and has no published Mac CPU latency ([IndicTrans2 card](https://huggingface.co/ai4bharat/indictrans2-en-indic-dist-200M)). With the o200k tokenizer, Hindi costs only about **1.35–1.4× the tokens of English** (it was ~3.8–4× under cl100k), so a Hindi question adds only 1–2% to cost ([token measurement on gold q054](../eval/gold.jsonl)). Do not draft in Hindi: HHEM-2.1-Open and MiniCheck-DeBERTa are English models ([HHEM card](https://huggingface.co/vectara/hallucination_evaluation_model)).

Ingestion reads only the pdfplumber text layer. A scanned PDF therefore ingests to zero chunks with no warning, and the API has no upload route even though the plan's impact-alert flow starts with "Upload" ([ingest.py](../backend/app/ingest.py); [api.py](../backend/app/api.py)). A one-hour check that reports "page N has no text layer; OCR needed" protects against a judge handing over a scan. OCRmyPDF with Tesseract `eng+hin` is the optional next step ([OCRmyPDF](https://github.com/ocrmypdf/OCRmyPDF)). A full runtime upload needs per-chunk embedding caching first, because the current embedding cache is keyed on a hash of *all* chunk ids, so one new document re-embeds the whole corpus ([retrieve.py](../backend/app/retrieve.py)). At the measured ingest cost of about $0.031 per document ([eval/cassettes](../eval/cassettes)), one live upload is affordable with a $0.05 cap. It is 4–6 hours of work, though, so it sits below the cut line.

### The demo path has failure modes that cost nothing to remove

Several demo-path problems have zero-cost fixes. `db.connect()` opens a new connection and runs the whole schema DDL on every call, with no WAL mode and no indexes ([db.py](../backend/app/db.py)). WAL lets readers and the single writer run concurrently ([SQLite WAL](https://www.sqlite.org/wal.html)). `llm.structured` sets no timeout, does not handle `message.refusal` or `content is None`, and checks the spend cap non-atomically across threads. A `CacheMiss` in replay mode comes back as a bare HTTP 500 ([llm.py](../backend/app/llm.py); [api.py](../backend/app/api.py)). `GET /impact/{report_id}/export.md` ignores `report_id` and re-runs `impact.run`, and every `POST /impact` re-inserts the same items, so the review queue doubles each time a judge clicks ([impact.py](../backend/app/impact.py)). Maker-checker refuses sign-off only when `actor == "officer"`, so any other string, including the maker's own name, can approve. The audit log stores the raw question and draft, leaves `corpus_hash` NULL, and the question itself is sent to the planner without redaction ([api.py](../backend/app/api.py); [audit.py](../backend/app/audit.py); [service.py](../backend/app/service.py)).

Ingest-time injection defence checks only white fill colour. It does not catch tiny fonts, off-page text, invisible render modes or *visible* imperative text such as "ignore previous instructions" ([ingest.py](../backend/app/ingest.py)). OWASP's LLM01 guidance asks for exactly the controls the system already has: deterministic output validation, segregation of external content, human approval and adversarial testing ([OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)). A narrow lexicon flag at ingest closes the visible-text gap for $0. Wrapping evidence in delimiters would change the prompt, so skip that.

### Prove the verifier does the work with $0 ablations

The eval harness is already above hackathon standard. It has Stanford-style labels, a deterministic fabricated-quote check, Wilson CIs, a frozen test split, a baseline and a fresh set written by a stronger model ([run_eval.py](../eval/run_eval.py)). What it lacks is evidence that each check matters. The most persuasive addition is a **verifier-ladder ablation**: switch off one check at a time (ids, in-force status, quote location, number binding, entailment), re-score from cached drafts, and count how many wrong or superseded sentences would then have reached the user. "Removing the in-force check lets N superseded quotes through" is the sentence that proves code decides. Turn the repair round and the LLM judge off during ablations, because their calls would miss the cache.

Next comes a **risk–coverage curve**: sweep `TAU_RETRIEVAL` and `TAU_ENTAIL` and plot selective accuracy against answer rate, with the chosen operating point marked. Recent work argues that AURC shows whether a system can operate at a stated risk level better than AUROC does ([arXiv 2603.21172](https://arxiv.org/html/2603.21172v1)). Research also gives a principled way to state the threshold. CiteGuard treats each claim–evidence score as a p-value and applies Benjamini–Hochberg. On FEVER and NQ it cut the false-discovery rate among accepted claims from 28–31% to below 10% while keeping 86–92% of supported claims ([CiteGuard, ICML 2026](https://icml.cc/virtual/2026/poster/64935)). Split-conformal abstention bounds the hallucination rate the same way ([Conformal Abstention, arXiv 2405.01563](https://arxiv.org/pdf/2405.01563)). With about 113 labelled items the guarantee is loose, so present it as "calibrated on n=113, marginal under exchangeability", not as a hard bound.

Then add recall@k for dense, BM25 and hybrid retrieval to the main report. An RBI peer repo found that **BM25-only beat hybrid** on RBI text, so check yours ([rbi-circulars-rag](https://github.com/srini2k03/rbi-circulars-rag)). Add the 2×2 abstention and 3×3 contradiction matrices the plan promised, a paired bootstrap CI against the baseline, and a two-person blind spot-check of 20 fresh items with Cohen's κ, which the README still lists as pending. IndiaFinBench shows why the scoring rule must be stated: on 406 RBI/SEBI items, strict-match and LLM-judge rankings were uncorrelated (Spearman ρ −0.273), and the judge rescored 93.9% of one model's strict errors as correct ([arXiv 2604.19298](https://arxiv.org/abs/2604.19298)). A small red-team set of about 15 items (visible injected footers, smuggled numbers, Hindi injection, homoglyph quotes, a fake "Substituted vide…" footnote) costs about $0.09 for one live run and gives FREE-AI-style adversarial-testing evidence.

## Nobody else ships proof, time and silence together

### Open-source platforms cite but do not check

The big RAG platforms all show citations, but none checks a quote verbatim, gates on entailment or knows that a rule can be superseded. RAGFlow (94.6k stars, 1.0.0 released Nov 2026) offers grounded citations, chunk visualisation and a "Timelines" knowledge compilation ([RAGFlow](https://github.com/infiniflow/ragflow)). Kotaemon has in-browser PDF highlights with relevance scores ([Kotaemon](https://github.com/Cinnamon/kotaemon)). PaperQA2 does contradiction detection over scientific claims, with no validity windows ([PaperQA](https://github.com/Future-House/paper-qa)). Where they beat us is UI polish, chunk inspection and parsing breadth, so the UI track matters.

The closest small peers share the thesis but stop short. Axiom Engine checks verbatim quotes and has an opt-in "Conflicted" tier, but it compares web sources with no notion of time or condition ([Axiom](https://github.com/FurkhanShaikh/axiom-rag-engine)). The two serious RBI repos are srini2k03/rbi-circulars-rag (2,000+ notifications, 36 retrieval configurations with bootstrap CIs, a browser-only demo) and Credit Assist (3 credit Master Directions, paragraph-lookup routing, 83% on a 15-question holdout) ([rbi-circulars-rag](https://github.com/srini2k03/rbi-circulars-rag); [Credit Assist](https://github.com/anuragthakur73/rbi-master-directions-assistant)). Neither reconstructs amendment versions or triages contradictions. The srini2k03 repo also supplies the best pitch evidence for a code verifier: on the same 155 answers, its **LLM-judge faithfulness was 0.953 and its NLI faithfulness 0.212**. Judge-only scores flatter answers that a checking model does not support.

Temporal and legal-graph work confirms the design rather than competing with it. Graphiti keeps facts "invalidated, not deleted" with validity windows, but it is generic agent memory ([Graphiti](https://github.com/getzep/graphiti)). The Brazilian Senate's SAT-Graph RAG separates abstract legal Works from versioned Expressions and models legislative events as Action nodes, which matches clause_key versus version rows and the WITHDRAWS/AMENDED_BY edges here. No public code was found ([arXiv 2505.00039](https://arxiv.org/abs/2505.00039v5)). TruthfulRAG-style exponential time decay is the wrong model for law: a rule does not fade with age, it stays in force until withdrawn ([Conflict-Aware-Graph-RAG](https://github.com/eeshsaxena/Conflict-Aware-Graph-RAG)).

### Research says the design choices are right, and newer checkers add only a little

On the LLM-AggreFact leaderboard, the best CPU-sized checkers are FactCG-DeBERTa-L (0.4B, 75.6) and MiniCheck-Flan-T5-L (0.8B, 75.0). The 7–8B models gain only 1–2 points ([LLM-AggreFact](https://llm-aggrefact.github.io/)). LettuceDetect adds token-level spans at 79.2 F1 on RAGTruth (large) and is actively maintained, while MiniCheck, AlignScore and RefChecker are stale or archived ([LettuceDetect paper](https://arxiv.org/html/2502.17125v1); [LettuceDetect repo](https://github.com/KRLabsOrg/LettuceDetect)). There is a structural reason not to swap checkers now. In this ladder, a second-opinion model can only *pass* sentences HHEM failed, so adding one loosens strictness. A checker that can only *block* tightens strictness but raises over-refusal, which is already the main gap. Run FactCG or LettuceDetect offline as a comparison column, not in the live path.

Temporal benchmarks published in 2026 reach the same conclusion this system is built on: LLMs apply the wrong version of a law unless validity is a hard constraint. They include German post-cutoff amendments, LexKairos, LawInForce-eCFR and NitiBench+ ([arXiv 2605.23497](https://arxiv.org/html/2605.23497); [NitiBench+](https://arxiv.org/pdf/2611.03576)). No source shows GraphRAG or LightRAG beating hybrid retrieval on legal QA. One comparison found hybrid modes most accurate ([CEUR-WS Vol-4079](https://ceur-ws.org/Vol-4079/paper6.pdf)), and StrucChunk reports that generic rerankers can hurt legal retrieval ([arXiv 2610.26313](https://arxiv.org/pdf/2610.26313)). That fits your own reranker A/B (28/32 either way). Keep the typed citation graph and the optional reranker off.

### SaaS sells links and obligation maps, not provable answers

Stanford RegLab found Lexis+ AI and Ask Practical Law AI wrong more than 17% of the time and Westlaw AI-Assisted Research more than 34%. It named "misgrounding", where a real citation does not support the claim, as a failure mode of its own ([Stanford HAI](https://hai.stanford.edu/news/ai-trial-legal-models-hallucinate-1-out-6-queries)). Lexis flags citations it cannot link for manual validation, and Shepard's checks whether a case is still good law ([LexisNexis](https://www.lexisnexis.com/community/insights/legal/b/thought-leadership/posts/legal-ai-citation-integrity)). Neither checks that a quote supports the sentence. The incumbents also opted out of the 2025 Vals legal-research benchmark ([LawNext](https://www.lawnext.com/2025/10/vals-ais-latest-benchmark-finds-legal-and-general-ai-now-outperform-lawyers-in-legal-research-accuracy.html)), so publishing your own abstention rate and risk–coverage curve is itself a differentiator.

RegTech's unit of value is the obligation map. AscentAI calls obligations "the unit of RegTech change", maps them to policies and controls, and shows side-by-side change text ([FinTech Global](https://fintech.global/2026/10/30/why-ascentai-makes-obligations-the-unit-of-regtech-change/)). Compliance.ai, now owned by Archer, auto-maps regulatory changes to internal policies ([Business Wire](https://businesswire.com/news/home/20240220502745/en/Archer-Acquires-Compliance.ai-to-Drive-AI-Powered-Regulatory-Compliance-and-Risk-Management)). Your impact alert is therefore table stakes in RegTech. What sets it apart is the verbatim quotes on both sides and a code-checked conflict rationale. In India, TeamLease RegTrack tracks RBI obligations as checklists ([RegTrack](https://teamleaseregtech.com/product-services/regtrack-financial-institutions/)), and NYAI claims "citation-backed" output without describing a method ([Tribune India](https://www.tribuneindia.com/news/business/indias-compliance-regtech-moment-nyai-emerges-as-the-countrys-first-purpose-built-legal-ai-platform-for-enterprise-grade-regulatory-intelligence/)). Third-party estimates put Harvey at roughly $1,000–1,200 per seat per month ([Spellbook](https://www.spellbook.com/learn/harvey-ai-pricing)), well out of reach for a Tier 3 co-operative bank.

## Cold loads and repeated local work set the latency, not OpenAI

The latency story has to be fixed before it goes on a slide. The README says "local compute p50 2.5 s" one question at a time. The fresh eval under 4 workers shows p50 **54 s** and p95 **143 s**, because the workers queue on NLI and embedding models behind a global lock. The 14-question canary, served almost entirely from cassettes, still shows **p50 4.2 s and p95 14.4 s** ([eval/reports](../eval/reports/); [verify.py](../backend/app/verify.py)). The tail is therefore local. Every model (bge-small, HHEM, MiniCheck-Large, Presidio and spaCy, the BM25 index) loads lazily on the first question. `build_evidence` re-embeds every sentence of every candidate chunk on every query, which is likely hundreds of bge forward passes. HHEM and MiniCheck each run one pair at a time ([service.py](../backend/app/service.py); [retrieve.py](../backend/app/retrieve.py)). At 2,312 chunks, dense search and bm25s are sub-millisecond, so FAISS, hnswlib or a smaller top-200 would buy nothing.

Item 1 comes from standard model-loading behaviour. HHEM's own card gives about 1.5 s per 2k-token input on x86 CPU and under 600 MB of RAM ([HHEM card](https://huggingface.co/vectara/hallucination_evaluation_model)). The quantisation numbers are references, not your models: Optimum's dynamic int8 sped DistilBERT up 2.48× at p95 while keeping 99.72% of fp32 accuracy ([Phil Schmid](https://www.philschmid.de/optimizing-transformers-with-optimum)). HHEM is custom remote code, so exporting it to ONNX is the riskiest item. FastAPI has native SSE through `EventSourceResponse` since 0.135.0 ([FastAPI SSE](https://fastapi.tiangolo.com/tutorial/server-sent-events/)), and the installed version is 0.165. Keep `/ask` as the generator's final event so the eval and the cassettes are untouched. Hold attempt-1 sentences until the repair decision rather than emitting retractions.

On the LLM side, OpenAI's guide lists fewer requests, parallelism and fewer output tokens as the levers ([OpenAI latency guide](https://developers.openai.com/api/docs/guides/latency-optimization)). Predicted Outputs do not apply to gpt-5.4 models ([predicted outputs](https://developers.openai.com/api/docs/guides/predicted-outputs)). Flex is slower and returns 429s ([flex](https://developers.openai.com/api/docs/guides/flex-processing)). "Fast" (formerly Priority) mode claims up to 2.5× speed at about 2× price ([priority](https://developers.openai.com/api/docs/guides/priority-processing)), which suits only a short demo window, if at all. Once items 0–5 are in, the warm p50 should feel like 1–2 s on screen. Quote only the timer output, never these estimates.

## Half a cent per answer, and 40% of it is removable later

Measured from 3,761 cached responses, a question costs about **$0.0045 at list price**, or $0.0053 with the code's 20% safety margin. The gpt-5.4-mini **draft call is about 80% of that** (about 90% including repair retries). The plan call is about 6.5% and the judge about 3% ([eval/cassettes](../eval/cassettes); [eval_runs.csv](../eval/reports/eval_runs.csv)). Two facts stand out. About **48% of draft output tokens are hidden reasoning** (~165 of 346), because `llm.structured` sets `reasoning_effort="low"` while gpt-5.4-mini defaults to `none` ([gpt-5.4-mini model page](https://developers.openai.com/api/docs/models/gpt-5.4-mini); [llm.py](../backend/app/llm.py)). And only **~25% of the draft prompt is evidence text**. The rest is per-sentence document tags (~22%), repeated context prefixes (~13%, half of them exact duplicates) and the system prompt plus schema. Prices are $0.75/$0.075/$4.50 per million tokens (input/cached/output) for mini and $0.20/$0.02/$1.25 for nano. Batch and Flex are 50% off. gpt-5.4-nano is now listed as **Deprecated** ([OpenAI pricing](https://developers.openai.com/api/docs/pricing); [gpt-5.4-nano page](https://developers.openai.com/api/docs/models/gpt-5.4-nano)).

Two levers fail the "proof or silence" test and should not be used. LLMLingua-style token compression drops words inside sentences, which breaks verbatim quote location and the coverage checks ([LLMLingua-2](https://arxiv.org/abs/2403.12968)). Semantic answer caches produce false hits (GPTCache made 54 false hits on 250 queries), and a compliance answer also depends on as-of date, bank profile and corpus version ([MeanCache](https://arxiv.org/pdf/2403.02694); [vCache](https://arxiv.org/pdf/2502.03771.pdf)).

**Recommendation for the hackathon: change no prompts.** Every lever that saves meaningful money edits the request. That invalidates the cassettes, which means paying to re-run dev, test and fresh (about $0.31 even at Flex rates) and losing the offline replay demo for every rehearsed question. Do the free accounting work instead. The ledger bills every prompt token at the full rate and never reads `cached_tokens` or reasoning tokens, so today's cost is an overstated upper bound ([llm.py](../backend/app/llm.py)). Then present the levers as a costed production roadmap: **$0.0045 → ~$0.0039 (safe package) → ~$0.0027 (draft reasoning none) → ~$0.0018–0.0022 (verifier-gated cascade)**. At 10,000 questions a month, that is about $45 a month today and $18–22 optimised. A one-time ingest of 5,000 documents costs about $156, or $78 on Batch, so a year costs roughly $700 today and $340 optimised. Strictness is unchanged in every tier because every path ends in the same verifier. Be candid on the cost slide: the system costs about 2.5× naive RAG per question, and per *accurate* answer it is $0.0062 against $0.0042 ([fresh.json](../eval/reports/fresh.json)). An abstention at the retrieval gate costs only the plan call, about $0.0003.

## The UI should show the verifier working, not another chat box

### What the category has standardised

Leading products present evidence in three steps of progressive disclosure: an inline marker, a hover preview of the quote, and a click-through that opens the source scrolled to a highlighted passage. NotebookLM shows direct quotes on hover and opens the passage on click ([NotebookLM Help](https://support.google.com/notebooklm/answer/16179559?hl=en)). Glean mutes the text around the snippet and falls back to a document-level link when it cannot match confidently ([Glean Developers](https://developers.glean.com/guides/chat/deep-linked-citations)). AlphaSense verifies each cited snippet after generation and opens the source highlighted, but it never shows that verification step ([AlphaSense](https://www.alpha-sense.com/blog/product/combat-generative-ai-hallucination/)). Legal tools add a validity flag to the citation itself: Westlaw's KeyCite uses yellow for negative treatment and red for no longer good law ([TR Help](https://thomsonreuters.com/en-us/help/cocounsel/skills/ai-assisted-research)), and Lexis added an orange "at risk" indicator ([LexisNexis](https://www.lexisnexis.com/community/amp-insights/82/how-lexisnexis-is-building-trust-in-ai-for-legal-research-with-shepard-s-citation-validation-enhancements)). Gemini's "Double-check response" colours individual statements green or orange, but only after the fact and only on request ([Gemini Help](https://support.google.com/gemini/answer/14143489)). Shape of AI's guidance is to make broken or missing citations explicit, because filler in place of a missing source erodes trust more than an honest empty state ([Shape of AI](https://www.shapeof.ai/patterns/citations)). A research prototype that showed supporting and contradicting excerpts for each claim got users to a source in 103 s instead of 152 s, n=20 ([arXiv 2510.00361](https://arxiv.org/html/2510.00361v1)).

The secondary screens also have mature precedents. legislation.gov.uk serves point-in-time URLs with a timeline of changes and a box of changes not yet applied ([legislation.gov.uk](https://www.legislation.gov.uk/ukpga/1991/22/section/79/2023-03-10)). eCFR compares any two dates with purple/orange as a colour-blind-safe diff option ([GWU guide](https://law.gwu.libguides.com/federalregulatory/updating)). Abstention is the weakest-designed state across the industry: products fall back silently, leave claims unhighlighted, or flag them for later.

### What to build, and where to beat the references

Build one hero screen first, because it will carry about 60% of the demo. A top bar holds the question, an **As-of** control, a **bank profile** chip ("UCB · Tier 3") and an EN/हिं toggle. A left rail lists past questions with outcome dots and links to Conflicts, Alerts, Reviews and Audit. The centre column (max ~720 px wide) shows the outcome badge, a Proof Meter reading "draft 4/6 → 4 proven · 2 withheld", sentence rows with citation chips, a collapsed **Withheld (n)** tray, calculation working, and the actions Send for review, Export PDF and Copy with citations. A resizable right pane renders the PDF page with a bbox highlight and the verbatim quote in serif, with status and valid-from/valid-to dates. On a CONFLICT it switches to a two-column clause comparison.

```
┌ Proof-or-Silence │ [ask…………………………] │ As-of 23-Nov-2026 ▾ │ UCB · Tier 3 │ EN/हिं ┐
│ History   │ ● ANSWER   Proof 4/6 drafted → 4 proven · 2 withheld │ PDF p.7  [▒▒ highlight ▒▒]   │
│ ● q1      │ Sentence 1 ……………… [KFS §5.2 · p.7 ●]              │ "verbatim quote in serif…"   │
│ ◐ q2      │ Sentence 2 ……………… [MD-PP §5(i) · p.3 ●]           │ ● IN FORCE 01-Jan-2026 → —   │
│ Conflicts │ ▸ Withheld (2): "…5%…" — no supporting clause      │ View clause history →        │
│ Audit     │ ▸ Show working (EMI ₹21,695.58, computed by code)   │                              │
└───────────┴────────────────────────────────────────────────────┴──────────────────────────────┘
```

Five design moves let this beat the references. First, **show the negative space**: withheld sentences and their verifier reasons can be inspected, which none of the surveyed products offers. Second, **put validity on the chip**: a solid green pip for in force, a hollow grey struck-through pip for superseded. Nobody does this for regulations as of a chosen date. Third, **make ABSTAIN a dignified, designed state**. Use a calm slate-blue card, not red, listing what was searched (documents, as-of date, profile), the nearest clauses with the reason each was rejected ("NBFCs, not UCBs"; "superseded 01-Apr-2021"), and what would unblock the question. Fourth, **one global as-of date** drives answers, timelines and conflicts together, instead of eCFR's separate compare mode. Fifth, a **visibly verifiable audit chain**: a "Verify chain" button ticks each row green, with truncated `prev_hash → hash` in monospace.

One correction to the "live verify" idea in the UI research matters for honesty. The research proposed streaming the draft in grey and then striking sentences out. That would put unverified text on screen and contradict the README's claim that no unverified sentence reaches the user. Stream **placeholder rows** ("verifying sentence 3 of 5…") instead, reveal the text only when its verdict arrives, and send rejected sentences straight to the labelled Withheld tray. The animation stays and the guarantee holds.

For style, aim for a "regulator's reading room" rather than an AI startup: warm off-white paper, slate neutrals, one ink-blue accent, hairline borders, a 6 px radius, and no gradients, glass or 3D orbs. Outcome badges always combine an icon, a label and a colour (green, amber, magenta and slate-blue), and diffs use purple for the bank and orange for RBI. Use IBM Plex Sans and Plex Sans Devanagari for UI text, so Latin and Devanagari share metrics; a serif for verbatim law text; Plex Mono for circular numbers and hashes; and tabular numerals throughout ([IBM Plex Sans Devanagari on Google Fonts](https://raw.githubusercontent.com/google/fonts/2796410152d4f9524b68ed46e69c1b60f8e0f7c3/ofl/ibmplexsansdevanagari/METADATA.pb)). India's GIGW 3.0 standard asks for a prominent language switch, Unicode text, Hindi fonts tested across browsers, and WCAG 2.1 AA ([GIGW 3.0](https://guidelines.india.gov.in/?p=9990); [GIGW scope](https://guidelines.india.gov.in/scope-and-objective/)). Use Indian digit grouping (₹12,34,567.00) and unambiguous dates (01-Apr-2025). In Hindi mode, never translate a verbatim quote; show an optional gloss labelled "अनुवाद (सत्यापित नहीं)". Light theme by default, dark as a projector toggle, and respect `prefers-reduced-motion`. Hover does not exist on touch screens, so citation cards need a tap or bottom-sheet fallback.

On the technical side, react-pdf 11 (MIT, React 19) with absolutely positioned highlight divs scaled by `page_width / width` is a 1–2 hour job. The dedicated highlighter libraries are stale and pinned to React 18 and pdfjs 4.4 ([react-pdf](https://github.com/wojtekmaj/react-pdf); [npm react-pdf-highlighter](https://www.npmjs.com/package/react-pdf-highlighter)). The backend has to expose page width and height, which are stored in `pages` but returned by no endpoint, plus a route that serves the PDF file if none exists yet ([service.py](../backend/app/service.py); [api.py](../backend/app/api.py)). Watch one cost trap: moving the as-of control or asking a new question changes the evidence pack, so the request misses the cassette and calls OpenAI live. Pre-record the demo question at the two or three dates you will show (about $0.005 each), and give the UI a "rehearsed questions" mode that only serves cached answers when the network or the budget is at risk.

## Conclusion

The research changes what "next" means for this project. The competitive scan found no product, repo or paper that combines located verbatim quotes, as-of validity, typed contradiction triage and code-enforced abstention. The gap with the field is real. What separates a strong entry from a winning one is whether a judge can *see* that gap and *trust* the numbers behind it. So the highest-value work is mostly not new capability. It is reclassifying refusals, replacing a tautological score with a draft-to-final story, ablating the verifier to show each check earns its place, and drawing the withheld sentences on screen. Nearly all of it is free because the cassette design makes re-scoring offline cost nothing. That design is itself worth a sentence in the pitch.

The second insight is that money is no longer the binding constraint; the cassettes are. Each prompt edit that would cut tokens 7–18% also throws away a free, repeatable eval and an offline demo. Until judging is over, the right cost move is to measure honestly (cached tokens, reasoning tokens, per-stage timers) and present the roadmap with arithmetic. Spend the remaining dollar on what only live calls can buy: an adversarial set, Hindi answers and a safe reserve for the demo.
